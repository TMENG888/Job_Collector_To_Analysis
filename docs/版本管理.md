# 本机源码版本管理

## 唯一开发入口

直接在当前“爬虫系统”目录修改、检查和提交源码，不再把另一个发布副本当成当前运行源码的最新版本。

本次承接 GitHub 原有 main 历史，不重建无关历史。`origin` 仍指向 `https://github.com/TMENG888/Job_Collector_To_Analysis.git`。本地提交不会自动上传；公开发布需另行审核及授权。

为节省 C 盘空间，当前目录中的 `.git` 是指向 E 盘对象库的小文件：

```text
E:/Codex/archives/job-collector-source-20261026.git
```

不要删除该目录或把它当作可再生缓存清理。单独复制 C 盘源码目录不等于备份完整 Git 历史；E 盘不可用时 Git 操作会失败，但不改变已有生产数据目录。迁移电脑时使用完整仓库克隆或 Git bundle，不直接照搬旧 `.git` 指针。

## 日常使用

在源码根目录执行：

```powershell
git status --short
npm run check:git
git add -- 路径/修改的源码文件
git diff --cached --stat
git diff --cached
git commit -m "简述本次修改"
git log -5 --oneline
```

不要为了还原代码执行 `git reset --hard` 或覆盖运行目录。需要旧版本时先查看差异，或在 E 盘建立独立 worktree 测试，不覆盖正在运行的源码。

## 数据与凭据边界

`.gitignore` 按源码范围准入，并排除：

- `ui_data`、任务输出、数据库、原始采集数据、断点、日志、运行缓存。
- PDF/DOCX 简历、表格数据、原始图片、密钥、环境变量文件及常见会话文件。
- node_modules、浏览器运行时、Python 环境及下载的大模型。
- 一次性探测、调试与数据审核脚本。

原已发布的五个固定 LR 模型作为产品资源保留，并校验已发布 SHA-256；不是把训练材料或用户新训练模型一并提交。新增产品源码位于 work/ 的其他子目录或其他扩展名时，需显式审核并调整准入规则。

本机启用 `core.hooksPath=scripts/git-hooks`。提交前会扫描实际暂存区：阻止运行数据、大文件、已知密钥特征、未审核模型以及遗漏的相对源码依赖；不打印匹配到的密钥内容。

这不是完整 DLP 或历史泄漏审计。仍需人工检查 diff，不能仅依赖忽略规则或模式扫描。当前源码与文档仍有本机路径和历史验收说明，本次本地保存不代表已通过公开发布审核。

其他电脑启用相同提交保护：

```powershell
git config core.hooksPath scripts/git-hooks
```

需要 Node.js 22 或更新版本。运行测试请把临时文件、输出及缓存显式设在 E 盘；生产配置、断点和登录资料继续保留原位置。

## 备份

源码提交后可生成独立备份，输出路径使用 E 盘的独立文件名：

```powershell
git bundle create E:/Codex/archives/job-collector-source-20261026.bundle --all
git bundle verify E:/Codex/archives/job-collector-source-20261026.bundle
```

bundle 只包含已提交的 Git 历史，不含被排除的私有数据，也不含尚未提交的工作区修改。生产数据库与断点需继续使用已有任务备份机制。
