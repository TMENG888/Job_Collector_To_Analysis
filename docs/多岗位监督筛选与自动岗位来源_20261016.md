# 多岗位独立逻辑回归与自动岗位来源

## 交付状态

源码和工件已更新，新增独立岗位分类器注册机制、原文标注训练和公司/近重复隔离评测。不是把“数据分析”模型复用于所有岗位。主8788只读检查仍返回旧版1.14.0、没有insightSourceRole能力；本轮未停止或重启主服务，没有启动真实采集，没有覆盖主报告。历史报告不会随源码变更，需重启后重新生成。

前端删除“指定岗位/岗位族”输入框及全部DOM读写，不是隐藏输入。根据选择的采集任务确定目标，显示只读来源说明；kb://task/ID由后台解析并校验。任务主关键词优先于带有城市/数量的任务标签，不会把标签当作额外关键词。文件导入无任务信息时仍自动识别；全部知识库的单岗位洞察会自动选取一个主岗位，不是多岗位合并统计，建议选择对应采集任务。兼容已有API的role参数，但有任务身份时以任务身份为准。

旧进程还未更新时，新前端会提示重启，不会把缺少role的请求交给旧接口产生“岗位不一致”错误。新服务GET /api/state应返回版本1.16.0和capabilities.insightSourceRole=true；GET /api/knowledge/status的role_screening.active列出当前实际启用模型，pending明确未上线原因。

## 共同数据通路与安全

1. 注册表只包含通过门槛的工件，清单和各JSON权重都固定SHA-256校验。缺失/损坏报错，不能静默换旧规则或借用其他岗位模型。JSON无可执行反序列化，无网络请求；运行期纯Node，不要求Python。
2. 洞察与知识库使用同一岗位工件、同一阈值、同一输入预处理。输入仅标题及原始正文，固定字符2–4gram TF-IDF/逻辑回归。没有标题直通；查询关键词、技能字段、薪资不进入分类特征；词云仅展示。
3. 正文少于80/多于9000字符、缺标题、职责全无已知特征：待复核，不计入该岗位族统计。未知岗位和未通过发布门槛岗位明确保留旧方案，不自动在线拟合。
4. 知识库派生视图在标题/工程上下文规则之后应用监督分类，防止规则重新放回已排除岗位。旧洞察标签不能复活被模型拒绝的同岗位成员；其他不相关岗位成员独立保留。缓存带岗位模型及准入版本。
5. 生产原始raw/job_versions、人工标签及历史报告不批量改写、不删除。分析读取固定SQLite快照，不要求CSV导出。

服务级人工回退：启动时JOB_ROLE_SCREENING=legacy回退所有监督岗位，或JOB_DATA_ANALYSIS_SCREENING=legacy仅回退数据分析；需重启服务并重新生成报告。非法值报错。不提供聊天开关绕过准入。
