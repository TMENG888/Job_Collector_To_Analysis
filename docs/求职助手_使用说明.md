# 岗位决策助手

入口：现有控制台左侧“求职助手”，默认 http://127.0.0.1:8765/?view=assistant 。端口可用 `JOB_UI_PORT` 配置。

![多会话聊天工作区（合成数据演示）](images/09-assistant.jpg)

入口已改为纯聊天工作区，不再要求选择任务类型、填写筛选表单或勾选岗位。可以连续说：“北京、三年经验、本科的岗位有哪些？”→“换成上海”→“对比前两个岗位”→“给我一份准备计划”。上方条件条显示当前记住的条件，证据卡有岗位序号和稳定的知识库岗位键。

配置文本模型后，发送聊天消息默认由模型规划和调用限定系统工具：岗位检索、市场统计、简历匹配、岗位对比、准备计划，以及采集任务列表、进度、日志与操作方案。岗位工具只读；创建、启动/断点续采、暂停、导出必须经确认卡片执行，不由模型自行确认。每轮最多6次模型请求、10次工具调用，总模型执行限时110秒（单请求25秒）；不支持任意命令、自动投递、联系招聘者或绕过验证。未配置模型时使用本地规则模式，复杂配置可使用任务表单；模型失败时保留实际工具结果。兼容API可显式传 `useModel:false` 禁用本轮模型调用。

## 聊天采集闭环

可依次说：“查看采集任务列表” → “查询嵌入式软件开发采集任务的最新进度” → “查看采集日志” → “断点续采” → 核对卡片并点击“确认执行”。新任务示例：“帮我采集嵌入式软件开发岗位数据”会准备“创建并启动”方案，点击“确认创建并启动”后才创建和启动；模型不能将采集请求降级为仅创建。明确说“创建嵌入式软件开发采集任务，目标15000条”或“不启动”则仅创建，需点击“确认仅创建”，任务显示“待启动”。历史仅创建方案不会自动升级；已有任务使用启动/续采，不重复创建。暂停与导出最新数据同样需要确认。

确认方案有效10分钟，绑定当前会话、任务ID及任务状态/配置。目标、关键词、城市、平台、节奏和警告均可核对；数字目标不得由模型猜测或改写。新方案替代该会话旧的待确认方案。确认接口 `/api/assistant/action` 只接受会话ID、操作ID与确认/取消决定，不能回传修改后的业务参数。重复确认返回已保存回执；执行中断导致结果不确定时不自动重试，应先查任务列表与日志。任务状态/配置已变化或方案过期需重新准备。

采集管理直接调用既有后端业务接口，不模拟页面点击、不通过CSV中转。候选量、去重入库量和最终交付量分开显示；卡片是查询时快照，点击“查询最新进度”读取最新数据。启动和导出回执仅代表请求已提交，不代表后台已完成。沿用既有断点、资源检查、渠道锁、自动归集去重与导出覆盖机制。停用渠道不会恢复；登录与验证码仍由用户人工处理。尚未开放洞察/打标的写操作，后续沿此工具协议扩展。

默认加密会话目录为 `ui_data/assistant_private/sessions/`。可用 `JOB_ASSISTANT_SESSIONS_DIR` 或本机 `ui_data/assistant_private/storage.json` 的 `sessionDirectory` 指定绝对路径；此私有配置不随源码发布。

简短的“确认并采集”会定位本会话待确认方案并重现卡片，不直接执行。过期方案重新校验后准备新卡，仍需核对并点击“确认执行”；取消或已结束方案不能复活，多张方案不能猜测目标。任务标签只供展示，搜索关键词来自关键词字段，不把“测试工程师-北京-8000”之类标签拼入搜索。工具失败保留具体脱敏原因，不以任务列表代替执行回执。

![采集方案确认卡（只读演示，不能启动采集）](images/10-collection-confirmation.jpg)

底层是统一岗位SQLite知识库＋本地关键词加权检索，不是向量检索。可以直接问“智能体和嵌入式的技术要求与薪资，哪个更有性价比”，不需要换洞察报告。跨岗位比较列出各方向样本与同条件分层；技能数量不等于学习难度，不能直接判定性价比。薪资阈值如“20K以上”按招聘月薪中点过滤，并非最低薪资保证。匹配率是简历明确提及技能对技术标签的覆盖率，不是录用概率；不检查完整职业能力。准备计划为建议。

证据库读取所有已登记且归属有效的活动采集任务。默认仅检索有正文且原文规则纳入或同内容版本洞察纳入的记录，不含待复核记录。自动分类尚未在全部岗位方向通过人工准确率验收，应核验具体JD。岗位键稳定，按平台＋岗位ID全库去重；不同平台可能仍有同岗重复。无目标方向数据时明确提示，不借用其他岗位数据填补、不自动触发采集。约15秒增量归集，数据更新不清空对话筛选条件。

岗位数量和薪资分位数由代码计算。薪资使用3K–200K/月的招聘薪资中点，少于5条不显示分位数；跨方向比较默认排除日/时薪折算，并提供两侧至少5条有效薪资的同城市、经验、学历、用工分层。证据来自数据库当前内容版本与稳定岗位键，不再依赖CSV原文件行号。洞察和打标直接选择知识库范围，内部固定版本快照；人工批准标签验证正文证据后反馈知识库。CSV/Excel只作手工导入或可选下载，历史文件不删除。

没有独立简历表单。在聊天框直接粘贴正文（“简历：”开头最可靠；含教育/项目/工作经历等多个段落标题的正文也会识别），或点击输入框旁“＋ 附件”。支持TXT、Markdown、文字型PDF与DOCX，单份最多3MB、正文40000字、PDF最多40页。上传后显示待发送附件，点击×可移除；无需再输入问题，直接发送也可匹配。可拖放一份文件到聊天输入区。扫描PDF、图片和旧版DOC暂不支持；读取失败会明确提示，不把空文字当作成功。

附件通过本机接口在内存提取文字，不保存原文件；PDF/DOCX依赖本机Python运行时与pypdf，优先使用当前Codex捆绑运行时，也可通过 `JOB_ASSISTANT_PYTHON` 指定。解析限制解压大小和超时；不执行宏，不解包文件到磁盘。简历原文暂存本机服务内存，闲置30分钟或服务重启后清除，恢复历史如需匹配须重新提供。清空简历可发送“清空简历”。本地服务不记录请求正文。知识库更新保留筛选，后续统计和证据读取当前版本；已归档/不再可用的岗位会从最近选择中移除。

### 简历资格匹配（2026-10-15）

匹配不再只按技能重合排序。本机规则提取明确学历、在校状态、毕业届次及实习意向，先剔除明确的学历、届次与全职经验门槛冲突，再优先展示目标方向的实习岗位；校招和未明确实习名额的职位标为待确认。不从实习经历所在城市推断城市偏好，不将两段实习当成多年全职经验。该资格检查不覆盖所有院校、专业、到岗及业务条件，不表示一定符合全部要求或仍在招聘。

调用外部模型时，除技能和脱敏岗位证据外，还提供上述白名单画像（学历、是否在校、毕业届次、实习意向、规范化目标方向），不提供简历段落、联系方式、姓名或教育/雇主机构名称。普通聊天里的个人信息仍需用户自行避免输入。

ReAct 推理框架与 React 前端库分开识别；LangGraph 等明确提及技术可识别，但“提及/了解”不表示熟练。未提及标签只作为待核对信息，不代表不会，也不代表JD中每个标签都是必选项。

简历匹配后继续检索或调整城市仍保留画像；发送“不按简历”或“只看市场”可退出匹配上下文。用工筛选同时核对明确包含“实习”的岗位标题；标题与全职字段冲突会显示提示。模型回答重排岗位后，“前两个岗位”按回答中引用的先后绑定。

引用继续严格核对本轮证据。模型使用带省略号的岗位键时，仅在前缀能唯一对应本轮证据时展开为完整键；无法对应或引用缺失时最多请求一次纠正，仍受6次模型请求、110秒总限额约束。若失败，明确标为降级并保留真实本地匹配清单，不以知识库概览替代推荐，也不将失败回答标为模型成功。

证据卡与模型接收原始薪资及口径，日薪不作为招聘月薪展示。匹配轮的薪资统计仅针对本轮展示岗位，排除日/时薪折算；有效月薪不足5条时不发布分位数。技能频率和准备方向同样针对展示岗位，避免把全库高频技术误当个人必补项。

真实模型验收工具：`node work/verify_resume_matching_live.mjs <本地简历PDF路径> [ui_data目录]`。该工具在临时本机端口调用附件解析与多轮聊天API，使用已配置模型（有API费用），以只读方式打开知识库，不同步采集数据、不保存简历原文或测试会话、不执行采集和投递。默认包含广州追问用于测试条件保留，不代表简历本人偏好广州。更新源码不会自动重载已运行的生产服务；应在空闲窗口部署。

### 独立求职目标与同条件报价（2026-10-15）

求职阶段（实习／正式校招／社招）、毕业届次、城市、学历与薪资单位随会话独立保存。明确聊天意图覆盖旧条件和简历意向；例如简历写“实习”，仍可以说“改找2027届北京秋招”。正式校招不再沿用实习日薪。上方条件条显示当前目标，重启后保留白名单目标事实，简历原文仍只存内存。

报价问题依次完成资格检索、`salary_benchmark` 同条件薪资对标、`job_details` JD补查，再交给模型综合回答；条件不齐先澄清并保存任务；条件齐备再检索、分组对标与补查。补充缺失城市、届次或学历可继续同一轮报价主题，无需重新上传简历（服务重启后除外）。工具记录区分“系统预检”“模型调用”“本地兜底”，不会把兜底检索写成模型主动执行。

对标按当前岗位方向、阶段、城市、学历与已明确届次筛选，使用所有合格样本，不只统计展示的前8条。指定校招届次时，届次不明与不匹配岗位不进入主统计；不自动放宽。原始日薪、时薪、月薪、年包分别统计，月薪另列薪数分布；薪数缺失不假设12薪，日薪不折算月薪。每种单位不足5条不发布分位数。缺少必要条件会追问，不输出个人开价。

条件齐备且样本足够时，以原始报价区间中点的中位数作为谈判锚点，25%–75%为可谈参考，并列出简历与样本岗位的技术证据、资格待核对项及原始JD。技术提及数不会换算成涨薪；这是谈判建议，不是个人薪资预测、最低可接受价或录用保证。同平台岗位去重，跨平台同岗仍可能重复；招聘有效性需复核。

模型可直接提出必要澄清，不因未调用工具而一律判失败；涉及数据的回答仍需本轮证据。模型未取证时最多一次提示取证，引用错误最多一次修正，均不突破原限额。模型超时、认证或引用校验失败时，展示可读的薪资摘要和原始岗位证据，不仅显示命中数量，也不会发布失败模型的编造内容。

验证：`node work/test_job_salary_benchmark.mjs`（纯合成数据，无模型调用）；`node work/test_job_salary_benchmark_live.mjs --read-only`（只读本机知识库，不保存会话）；加 `--model` 才调用本机已配置模型并产生少量API费用。真实验收不启动采集，不修改任务或简历。

### 多城市任务 Agent 与数据准入 v4（2026-10-15）

可直接说“广州和深圳都可以”，每次最多4个城市、4个岗位方向。同一维度用 OR，不同维度用 AND；薪资按城市 × 方向分别统计，不能合并成个人报价。明确换城市会覆盖旧范围，排除城市单独记录。本人学历用于最低门槛核对，不再等价于只查相同学历；只有明确说“学历要求”才按岗位学历字段精确筛选。不从学校名称猜学历。

报价任务保存目标、步骤、缺失条件与已调用工具，澄清后继续。例如先问“智能体秋招报价”，再提供“广州深圳，27届”，最后说“本科”，无需重复全部问题。该状态随加密会话保存；简历原文仍只在内存。界面显示结构化任务和工具来源，不显示内部思考，也不声称实时流式显示推理。

模型每轮可进行6次请求、10次工具调用。每次工具结果回传模型后可继续补查；非法参数返回可纠正错误，不能自动放宽用户范围。新增 `task_status`、`data_quality_report`；检索、统计、对标可用 `cities` / `roles` 查询已确认范围的子集。不执行任意 SQL、命令或自由网页操作；采集写操作仍须点击确认卡片。

数据治理采用版本化派生视图 `admission-v2-20261015`，不覆盖原始岗位、历史版本或人工标签。旧观察即使原文未变也会按新规则重算；版本加入缓存键，数据版本变化自动失效。主岗位标题、真实工程职责与任职要求/加分技能分别保存；信息安全岗仅提到 LangChain、人力/售后岗仅写“AI应用方向”不再自动纳入智能体开发。规则是保守准入，不是人工复核金标准，可能需要补充人工标注。

薪资解析统一保留原始单位，修复“7千-1.4万”被误解析为7万元的问题；日/时/年薪不再静默折算月薪。连续出现的相同“9.9-9.9千”标记疑似异常，保留检索记录、暂停薪资对标，不认定数据造假。学历未知、指定届次未知、届次歧义与明确关闭状态按相应用途排除或提示；“2026年应届毕业生”也识别为明确届次。不能保证岗位仍在招，薪资与资格仍需原站/招聘方核验。

同条件每组不足5条时保留岗位证据，拒绝发布分位数或个人开价；不混入其他届次、硕博岗、实习或全国数据凑样本。可明确提出扩大范围，或者先查询待确认岗位，但两者不能伪装成严格同条件结果。

验证：`node work/test_job_agent_admission.mjs`；`node work/audit_job_admission.mjs --read-only` 只读审计；加 `--model` 实测报价回答，或 `--tool-loop` 实测模型自主多轮工具接续（有API费用）。两者均不保存测试会话、不启动采集、不修改原始数据。

## 多会话聊天工作区

采用左侧会话列表＋右侧聊天布局，全局功能导航缩为图标栏。支持新建、切换、标题搜索、今天/昨天/近7天分组、重命名、删除与撤销；手机端通过顶部会话按钮打开抽屉。生成回答期间不允许切换，避免把回答放入其他会话。输入草稿和待发送附件只保存在页面内存，切换不会串入其他会话。

新对话保留旧记录，每个会话独立保存筛选、最近岗位选择和多轮历史，刷新页面或服务重启后可恢复继续追问。每个会话保留最近80轮展示记录；模型仍只读取有限最近上下文，不将全部历史一次外发。恢复的统计和引用是当时快照，继续问答使用当前知识库。浏览器localStorage仅保存当前会话ID，不保存聊天正文。

记录位于配置的加密目录（默认 `ui_data/assistant_private/sessions/`）：先压缩，再以AES-256-GCM加密，主密钥由Windows DPAPI当前用户保护；只有同一Windows账户可以正常解密，不防御已控制该账户的程序。识别为简历的用户消息保存通用占位符，不保存简历原文或附件文件。自动识别不保证识别无格式简历，请以“简历：”开头或通过附件提供。普通聊天记录属于本机历史，仍可能含未识别的个人信息，勿分享整个私有目录。删除会话从列表移除，但加密文件保留为 `.deleted.json` 供撤销；不是永久清除。磁盘满或文件不可写时保存失败会明确提示，原记录不被覆盖，不自动重复调用计费模型。

## 本地启动

正常新版控制台包含 `/api/assistant/context`、`/api/assistant/chat`、`/api/assistant/sessions`、`/api/assistant/session`（旧 `/ask` 和 `/reset` 兼容保留）。旧控制台未重新加载后端时，可以运行独立助手服务，不需停止现有采集：

`node work/job_assistant_service.mjs`

默认仅监听127.0.0.1:8791，页面遇到旧接口404时自动连接该本地服务。兼容独立助手默认连接旧主服务8788；发布版主控制台默认8765，因此启用独立助手前需设置 `JOB_UI_PORT=8765`（或实际主端口）。主服务不可用时明确报错。新版主控制台已内置助手，通常不需要独立服务；查询不改变业务状态，确认后的写操作通过主服务执行。

主控制台和独立服务使用同一加密会话目录，并通过逐会话文件锁避免并行覆盖。部署更新后需重启助手服务；采集运行时不要随意重启主控制台。

## 可选纯文本模型

![模型设置弹窗（合成演示，无密钥）](images/12-model-settings.jpg)

默认未配置外部模型，本地证据版直接可用。推荐先用纯文本模型；多模态可后续作为截图简历/作品集的解析入口，不取代检索与计算。

点击聊天页右上角“模型设置”，在弹窗中选择DeepSeek或通义千问，填写模型ID和新API密钥。支持关闭按钮、取消、Esc或点击遮罩关闭；关闭时清空未保存的密钥。聊天中发过的密钥应先在供应商控制台撤销重建。不要把密钥发到聊天、写进源码或版本库。DeepSeek默认ID为 `deepseek-flash`；请确认你的账户实际可用模型。只连接固定供应商HTTPS端点，不支持任意外部地址。

密钥使用Windows DPAPI当前用户加密，保存到项目非公开目录 `ui_data/assistant_private/model.json`。接口不返回密钥或密文，进程命令参数和日志不包含密钥；保存后输入框立即清空。通常只有同一Windows账户可解密，但不能防止已控制该账户/本机的程序读取。不要将配置文件分享或提交到版本库。保存后无需重启，不会自动发起计费调用。

输入框旁显示当前模型或“本地模式”。配置模型后发送消息即默认使用，可能产生调用费用；页面底部保留简短提示。模型读取脱敏最近对话、当前筛选条件、识别到的技能和少量JD片段，不发送附件正文。识别出的简历消息会转成本地简历，只给模型提取技能和通用匹配问题；“简历：”开头或附件最可靠。自动识别和脱敏不保证能识别所有无格式简历或隐私信息，普通聊天问题可能外发，请避免在问题里输入个人隐私。一个任务可能产生多次模型调用费用，建议启用供应商预算和限额。

AI补充建议和本地统计分开呈现，原始卡片为证据来源。无效引用丢弃，模型调用失败不丢失本地结果。
