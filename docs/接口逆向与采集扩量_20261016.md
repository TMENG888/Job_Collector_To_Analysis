## 就业在线 HTTP 直连（完整逆向）

**接口**：`POST https://api.jobonline.cn/jobtbao-es-api/elastic/api/position/common/v1/showlist?bodytarget=SEARCH_RESULT_PAGE`

**加密（全部逆向复现，长度/格式与真实 100% 吻合）**：
- `businessData = SM4(明文JSON, key=x, iv=A)`（去 `sm-crypto` 前缀），明文 = `{target, param:{positionName3:关键词, cityCode, sortType:1, pageorder:'DESC', ...}}`
- `E-CONTENT-PATH = "04" + SM2(`${x},${A},${y},${w}`, 服务器公钥, 1)`
- `E-SIGN = SM3("business" + businessData + "data")`
- 服务器 SM2 公钥硬编码于网站前端 bundle（非用户凭据）：`04 3f4a9673...917aa`

**关键**：需要完整的浏览器请求头（`sec-fetch-*`、`priority`、`msha`、`platform`、`testentype`、`trackplatform` 等），缺则超时。

**限制**：接口**无服务端分页**（每条件返回约20条）；靠 **关键词 × 城市** 组合扩量。实测 3关键词×3城市 = 180 条，去重无重复。

**实测**：3关键词×3城市 = **180 条**，无错误。

## 未完成项与边界

1. **前程无忧**：51job 自身签名（HmacSHA256）已逆向，`decode__1048` 为阿里云 WAF 指纹。但 WAF 实际拦截层是 **AliyunCaptcha 滑块验证**（页面显示"请按住滑块，拖动到最右边"，加载 22 万字节行为验证码 SDK），不是确定性的 `acw_sc__v2` 计算题。**已通过会话方案落地**（见下）。
2. **猎聘**：IP 级风控，需本机 IP 已通过验证或使用已登录会话浏览器。
3. **登录 cookie 到期**：约 1 周后智联会退回到匿名 60 条/城市，需重新运行登录助手。
4. **51job 滑块可能重复触发**：会话有效期取决于网站风控策略，再次触发时采集会 `waiting_human` 停下，需人工再过一次。

## 前程无忧会话方案（方案A）

**原理**：51job 的 API 需要本地会话生成的签名与 WAF 令牌，纯 HTTP 无法复现。改为：人工过一次滑块 → 会话保存在受管浏览器 profile → 采集器调用页面 Vue 客户端发起请求（签名/cookie 由浏览器自身生成，不重放静态签名）→ 捕获 `/api/job/search-pc` 响应。

**使用流程**：
```
cd "C:\Users\YS-Insight\Desktop\陈晓锋\爬虫系统\work"

# 1) 过一次滑块（一次性；若再次触发需重做）
node job51_session_helper.mjs
#    在弹出的浏览器中手动拖动滑块，确认看到岗位列表后回终端按 Enter

# 2) 解除该渠道的人工处理阻塞标记
node clear_channel_block.mjs job51 --confirm

# 3) 在控制台新建任务时选“混合模式”（http_preferred_browser_fallback），勾选前程无忧
```

**实测**：北京"销售工程师" `total=522`（完成采集 522 条）；上海 `total=1000`，采集到第23页（460条）时触发验证 → 采集器正确停止并保留断点（`verification_required`）。合计约 980 条入库。

**重要提醒（粘性失败与残留进程）**：
- 若采集失败，会在 `RPA_job51_状态.json` 写入 `stopChannel` 错误，下一次会因“上轮浏览器失败”直接跳过，不再重试。人工恢复后需**删除该状态文件**或走控制台的“人工确认验证”流程。
- 勿手动开同一个 `job51` profile 的浏览器；采集器通过受管浏览器 host 隔离管理。若遇 `浏览器启动失败...launchPersistentContext` 且提示“已在现有的浏览器会话中打开”，说明有残留 Chrome 占用 profile，关闭旧窗口后重试。

**边界**：不模拟滑块轨迹、不接入打码平台、不重放静态签名；滑块由本人完成，采集只复用已通过的会话。
