# 助手实时交互（2026-10-17）

## 界面行为

发送后立即显示执行进度，而不是等整轮响应：读取证据、核对条件、本轮计划、模型调度轮次、工具开始/返回/失败、引用核验与保存。工具结果就地更新，正文使用原有 Markdown 安全渲染并逐段呈现。滚动仍尊重用户当前位置，不强行拉回底部。

完成后默认收起“执行记录与数据依据”，正文和复制/编辑/重新提问等原有操作保留。待用户确认的采集卡片、重要失败提示保持可见，不藏进折叠区。

“停止回答”只中止本轮流式请求，不撤销已经确认并提交的采集任务；应在采集中心核对实际状态。断线、超时不自动重发 POST，不自动重试创建任务或模型请求。

## 流式协议

`POST /api/assistant/chat` 使用 `Accept: text/event-stream` 启用 SSE；原 JSON 协议继续兼容。

- `phase`：可观察的阶段摘要，不是内部思考。
- `plan`：本轮结构化任务计划。
- `tool_start` / `tool_end`：工具 ID、白名单名称、状态、结果数量和耗时；不发送原始参数、密钥或简历原文。
- `answer_start` / `answer_delta`：经过现有证据与引用校验的正文。
- `done`：完整、可恢复的最终回合。
- `error`：本轮失败，前端保留已执行过程并提示核对状态。

连接每10秒发送心跳；浏览器断开时中止模型调用并在后续工具调用前检查取消。读取知识库等同步 CPU 工作不能被立即抢占，但不会在取消后继续启动模型或新工具。

模型请求启用真正的 provider SSE，聚合多轮工具参数碎片，并保持已有引用校验、工具白名单及人工确认边界。模型内部 `reasoning_content` 仅在瞬时的供应商续轮消息内使用，不展示、不写会话。未经核验的模型草稿不向界面发布；因此正文首字仍要等引用校验，等待期间展示真实执行进度。前端对核验后的文字做渐进呈现，不冒充尚未结束的模型思考。
