按用户选择，将“数据分析”岗位族切到已封存的监督模型。智能体、嵌入式及其他岗位族保留原筛选；这不是所有岗位族的通用分类器。原始岗位数据、历史报告和人工标签不删除，不重训或改变既有评估结果。

## 生产契约

- 版本 `data-analysis-tfidf-lr-v1`，C=10，纳入阈值0.55；固定字符2–4gram TF-IDF词表、IDF和逻辑回归权重。当前分析数据不参与训练或阈值调整。
- 输入仅岗位标题＋原始JD，经与离线模型相同的通用职责提取、头/中/尾420字符压缩。查询关键词、薪资、外部技能字段不作为分类特征。标题参与模型，但没有标题匹配直接纳入。
- 正文不在80–9000字符、标题缺失、职责全无模型已知特征时，单列待复核，不计入数据分析统计。此为生产安全边界，不表示这些岗位确实无关。
- 分数≥0.55纳入，否则排除；分数未经校准，不是正确概率。ngram贡献仅解释线性计算，不等同逐句职责证据或因果解释。
- 两轮隔离评估已确认存在误纳漏纳；新随机77个已判定样本只有5个正例，P/R各80%，P的95%区间约37.6%–96.4%。标签由Codex按源文给出，不是独立人工金标准。

## 共用通路

1. `work/data-analysis-classifier.mjs`：纯Node、惰性加载、安全JSON推理，工件SHA-256固定校验。模型缺失或损坏会报错，不静默回退关键词筛选。不需要Python、下载或外部API。
2. 洞察分析：`数据分析/数据分析师/商业分析/经营分析/统计分析/BI分析师`定位到数据分析岗位族，再逐条调用同一模型。词云提词仅展示，不影响纳入。报告记载模型版本、阈值、摘要及审计分数；待复核独立保留。
3. 知识库与助手：对当前内容版本重新计算派生岗位族。未通过数据分析模型的记录不能因旧分析标签重新成为数据分析；其他岗位族资格不因本分类器拒绝而删除。缓存键包含模型版本及数据治理版本。
4. 原始jobs/raw、job_versions不因本次模型替换而批量改写；刷新派生视图即可生效。历史报告保持原样，重新生成的分析采用新筛选。

状态入口：`GET /api/knowledge/status` 的 `role_screening.data_analysis` 提供版本、阈值、工件摘要。主报告的 `selection_contract` 和 `role_classifier` 提供本轮实际使用信息。
