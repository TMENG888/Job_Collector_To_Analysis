# 词云新词辅助审核

## 本次范围

保留原有规则抽取、岗位准入、词云布局和计频口径。新增本机 GLiNER 技能新词候选通路，不直接替换旧算法。工作内容、业务方向仍使用原口径；公司行业仍来自来源字段，不由模型从 JD 猜测。

入口：岗位洞察 → **新技术词候选 · 本机模型辅助审核**。选择全部知识库或一个采集任务，点击“扫描下一批20条”。无需导出 CSV，不会启动采集。

1. 模型只读当前活动任务的岗位正文，候选带岗位标识、正文版本、原文句子、优先/加分标记及模型分数（不是准确率）。
2. 核对词项确为该岗位的技术要求，再逐条批准或拒绝。批准只作用于该岗位，不自动传播至其他含同词岗位，也不影响岗位是否纳入分析。
3. 批准后，助手后续查询使用最新标签；点击“生成全量分析”后，新标签才进入新的词云报告。旧报告和快照不原地修改。
4. “已批准”页可撤销批准；“已拒绝”页可恢复待审。撤销后，助手不会从旧分析重新带回该补充词；旧报告仍保留历史统计，需重新生成。

同一岗位重复出现一个词只计一次。英文大小写与空白规范化只用于同岗位候选去重，不将不同技术做模糊合并。候选可能仍包含泛词或不恰当标签，必须人工核对。

## 安全与资源

- 模型：`urchade/gliner_multi-v2.1`，修订 `443d26d654e0324125a96bebd8e796c14ff2efe6`；声明 Apache-2.0。仅加载本地 safetensors 和内置 DeBERTa 编码器，不运行模型仓库自定义代码，不自动下载。
- 环境：`work/wordcloud_uie_env`；权重：`work/wordcloud_uie_models/gliner-multi-v2.1`。这些大型本地资产不应直接提交源码仓库。试验依赖版本见 `work/requirements_wordcloud_trial.txt`。未安装时返回不可用，原规则分析照常。
- 独立短生命周期 CPU 进程，2线程；服务不常驻模型。默认20条，接口上限50条，只允许一个批次执行，不自动全库扫描。
- 启动至少3.5GB可用物理内存、4GB可提交内存。运行期间再次检查资源，资源不足或超时安全停止；不会结束采集器或其他用户进程。已完成岗位扫描保留，可重试未完成部分。
- 排除公司介绍、福利及包含明确否定的句子，过滤现有规则已覆盖的技术、泛词、无原文跨度及拉丁词中间片段。混合正否定句暂整体跳过，宁缺勿误。仍不承诺所有新词均正确。
- 扫描缓存以岗位ID、正文哈希、流水线版本为键，重复扫描不会重复插入。岗位正文更新，旧批准不会应用至新版本；任务归档后候选不在活动列表展示。

## 数据通路

`原生SQLite岗位库 → 本地候选发现 → 候选逐条审核 → 同版本证据标签 → 知识库快照 → 重新生成岗位洞察/助手查询`

候选、扫描缓存和运行状态存于岗位知识库的 `skill_term_candidates`、`skill_term_scans`、`skill_term_runs` 表；批准记录存于既有 `labels` 表，不修改全局规则词典。

接口均为本机控制台接口：

- `GET /api/knowledge/skill-terms?state=pending&taskId=&limit=25&offset=0`
- `GET /api/knowledge/skill-terms/status`
- `POST /api/knowledge/skill-terms/scan`：`{"limit":20,"taskId":""}`
- `POST /api/knowledge/skill-terms/review`：`{"id":"候选ID","decision":"approved|rejected|pending"}`

写请求必须 JSON，同源与端口校验，不接受客户端指定模型路径、文件路径或命令。
