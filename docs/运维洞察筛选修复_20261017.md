# 运维洞察筛选修复

## 原因

失败快照 `0f15838f-44e5-48d0-b147-7b67726efd83` 包含13,158条记录。原通用方案按标题生成种子、从正文提词，要求至少两个独立高区分度词。实测旧方法前100候选中没有合格词；取消候选截断后也只有一个词同时满足种子覆盖和lift门槛，因此不是简单增加topK就能解决。通用方案在这批包含IT运维、非IT设备运维及邻近岗位的样本上不适用。

没有降低通用筛选阈值、按标题直接纳入、删除原始记录，或借用其他岗位的监督分类器。

## 本次方案和范围

仅岗位洞察的“运维/云平台”使用 `operations-evidence-v1`：人工配置IT对象词与运维动作，检查原始正文同一子句中的明确职责。只出现Linux、Docker等技能，或者只有标题/查询词，不直接纳入；缺少明确职责、非IT设施与其他主岗位冲突的记录待复核或排除。待复核不进入薪资、技能和城市主统计。公司介绍及福利沿用现有分节排除机制。

这是**规则型职责证据方案，不是TF-IDF＋逻辑回归**。词频仅供报告展示与审计，不训练权重。运维尚无通过验收的监督模型，未声称精准率或召回率达到某数值。存在漏收（尤其缺少职责详情、职责与对象被分句、混合开发运维等记录）和误收风险，需人工抽查。仅恢复洞察分析能力，不代表全部岗位分类或助手的知识库准入已统一升级。

其他已发布的四个监督模型、通用关键词算法、采集条件、平台限流、原始岗位数据不变。报告记录准确方案名称、版本、非监督状态、正文依据，以及独立复核清单。
