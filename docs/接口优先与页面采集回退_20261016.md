## 如何使用

1. 在新版采集中心选择“新建采集任务”。
2. 取数方式选择“接口优先，必要时浏览器页面采集（试验）”。界面新任务默认此方式，但接口不指定时仍默认纯 HTTP，已有任务不自动迁移。
3. 浏览器默认每条件最多3页、每渠道每轮最多200条，可在1–50页、1–10000条范围内明确设置。条数预算计算本轮详情处理量，历史 HTTP 数据不占本轮预算。
4. 按需勾选就业在线、前程无忧、猎聘等试验渠道；默认不自动勾选。纯 HTTP 模式将禁用这三个选择。
5. 配置关键词、城市、总目标后开始采集。页面适配尚需逐平台真实验证，不应直接以大目标压力测试适配器。

目标条数不是交付保证。有效字段完整、岗位相关、仍在招聘是不同维度；采集数量不能代替相关性/在招复核。就业在线当前配置为全国范围，不伪造城市筛选生效。

## 调度与数据保护

- 已验证 HTTP 渠道先运行；普通失败不阻止其他独立渠道。HTTP 阶段完成后，串行处理允许回退的页面渠道，并非所有渠道同时打开浏览器。
- HTTP 正常完成、正常空结果、分页停滞不触发换取数方式。仅明确的响应结构/传输故障在适配范围内可申请回退。
- 验证码、登录要求、401/403/429、挑战页及共享冷却不允许自动回退。已知验证/挑战记录在冷却后仍要求人工复核，不通过改渠道、换浏览器资料或换代理自动恢复。
- 未验证 HTTP 的渠道仅在没有已有错误记录时进入普通网页采集；不重复调用旧浏览器内客户端接口、不捕获重放签名/鉴权请求。
- 浏览器真正操作可见岗位链接、详情和“下一页”，不将浏览器会话 API 伪称为 DOM/RPA。
- 共享限流目录中的全局浏览器工作器锁限制一个页面采集工作器（跨控制台共享该目录时也互斥）；单工作器使用独立可见 Chrome 窗口，最多两个工作页。窗口完成/暂停后关闭，独立配置目录保留；不导入日常浏览器资料、不隐藏自动化、不安装规避验证插件。
- 浏览器页面操作共享 HTTP 的站点时钟，至少间隔4秒并加入抖动。网页自身资源和后台请求不能声称全部受此操作限速器控制。
- 继续保留2GB可提交内存/512MB可用物理内存保护，不为追求条数降低阈值；资源不足全局暂停。输出/归属异常停止继续工作。
- 原生 SQLite 写入继续使用任务归属校验、平台岗位 ID 去重、保留更完整字段、任务独立备份；不经 CSV 文件中转。
- RPA 断点保存在 `断点数据/RPA/<平台>/<关键词>_<城市>.json`，不改写或复用 HTTP 游标。分页停滞、不可核验空结果仅结束对应条件，其他可执行关键词/城市仍可继续。
- 渠道发生验证/页面结构等停止错误后保留状态，不会在自适应轮次无限重启。本版没有新增“人工已验证一键恢复”接口；需要人工复核和后续适配，不能以聊天确认或写布尔标记代替验证。
