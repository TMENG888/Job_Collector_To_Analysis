## 默认采集策略

新建任务目标条数可留空：`collectUntilExhausted=true`，`collectionGoal=available_scope`，`targetRows=null`。助手不得擅自补出一个目标数字，执行仍需用户确认卡片。

未填目标时不按有效条数提前结束，不伪造百分比或宣称“目标已达到”。仍受所选关键词/城市/渠道、分页/行数预算、最多151轮自适应调度、限流、低收益和资源保护约束；遇到验证或拒绝访问停止，不绕过访问限制。“本轮条件已处理”不等于整个平台数据穷尽。预算不是实际可采数量或交付保证。

明确填写数量的新任务保留按数量停止功能。经用户授权，旧版历史任务（无 `collectionGoal` 字段，包括归档任务）在服务加载时一次性迁移为无目标条数；同步渠道配置和岗位导出配置，保留原目标的迁移记录。不会自动启动任务、取消归档、修改断点或移除渠道分页/行数及频率安全预算；目录或配置缺失时不擅自重建，记录缺失路径。导出为手动操作，不是入库或洞察的前置条件。

## 边采集、边洞察

`渠道已提交记录 → 任务统一 SQLite → 约15秒同步 → 中央知识库 → 版本快照 → 岗位洞察`

在任务中点“用于岗位洞察”可读取当前已提交的中间数据；转移接口主动刷新本任务数据。原生写入和归集使用 WAL，中央同步同时检测主文件与 WAL 的变化，不漏掉尚未检查点的事务。

每次分析固定一个 `kb://snapshot/...`，新记录不改变已生成报告；需要最新数据时重新生成分析。发现的列表候选不一定已获取详情、通过准入或匹配目标岗位，洞察仍执行岗位筛选。助手查询和洞察无需 CSV 中转，手工导出保留。
