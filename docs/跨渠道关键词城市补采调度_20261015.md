# 跨渠道关键词与城市补采调度

> 后续策略更新：本日已强制[纯 HTTP JSON 采集](纯HTTP接口采集_20261015.md)，下文涉及浏览器渠道运行、旧计数和18:33部署状态均为历史记录。当前调度只派发已验证直连渠道；新隔离端到端测试改用 HTTP 适配器和模拟 JSON，不再启用就业在线浏览器。

## 修复的问题

旧的目标续轮只检查就业在线的 `round_limit`。某个关键词分页重复时，续轮直接结束，其他条件不能作为后备计划补量；首次触发分页保护还会错误地停止该渠道后续关键词。

现在控制台流水线使用 `work/collection_search_queue.mjs`，不再依赖就业在线的单渠道续轮器。初始采集结束后，按平台、关键词、城市检查断点，派发可执行条件。就业在线不是任务队列的总开关。

## 调度及边界

- 优先处理已配置的未完成条件。单轮最多派发 48 个组合，整个自动补采最多 151 轮。
- `pagination_stalled` 和 `legacy_pagination_unverified` 只阻止对应查询组合，不清除原断点，也不再次请求该条件。其他关键词、城市、渠道仍可执行。
- 登录失效、验证码、访问限制、限流或响应结构异常仍阻止相应渠道；不会通过换关键词继续试探访问限制。同一次补采记住受阻渠道，不因别的渠道成功而忘记它。
- 资源不足、输出故障、任务目录归属不符和用户暂停仍是任务级停止条件。
- 一批条件没有新增有效记录，只让这批条件让位，不直接终止后续补采。
- 保留各渠道原有分页、候选条数、请求间隔、重试、账号锁和独立备份策略。选择性续轮保留未执行渠道的数据和失败原因。
- 达到有效记录目标后不再生成下一批条件；队列耗尽或达到轮次预算时明确交付部分结果，不宣称平台全部采完。

## 相关关键词和城市范围

目前自动扩展采用保守字典，不是无限生成关键词。主关键词为“测试工程师”“软件测试”或“软件测试工程师”时，在既有条件没有可执行项且尚未达标后，依次补充：软件测试、自动化测试工程师、测试开发工程师、接口测试工程师、性能测试工程师。已配置的词不重复添加；其他更窄的岗位名称不自动换成宽泛岗位。其他岗位仍执行其已配置关键词。

新增词会先保存到任务，再同步公开渠道及智联配置，然后执行；重启和断点恢复不会丢掉已经启用的关键词。创建任务 API 可用 `adaptiveSearch: false` 禁用自动相关词扩展，禁用后仍处理已配置条件。

城市只使用渠道配置中已经选定、已经实现的筛选条件，不擅自添加上海、广州等新城市。前程无忧、智联、猎聘按其城市配置执行。公开渠道中当前只接入全国条件的平台，仍是全国查询，不能把其结果表述为已经按北京或深圳筛选。需要扩展真实任务的城市范围时，应明确修改任务配置，不能用轮次调度伪造城市支持。

## 可观测性

- 任务目录的 `采集调度状态.json` 保存本轮队列、各条件状态、激活的相关词、轮次及有效记录数，不包含会话凭据或岗位原文。
- 任务 API 新增 `collectionSchedule` 和 `adaptiveSearch`；日志新增 `[条件让位]`、`[相关关键词补采]` 及包含实际执行条件的 `[目标续轮]`。
- 结束原因包括 `target_reached`、`search_queue_exhausted`、`channels_blocked`、`round_budget_finished`，不把单个渠道的停止原因当作整个任务结束原因。
- “有效记录”仍是当前完整字段校验与平台岗位 ID 去重口径，不等于岗位相关性、仍在招或个人资格已经人工核验；岗位推荐和薪资统计继续走知识库的数据准入。

## 验证

- `work/test_collection_search_queue.mjs`：单条件停滞、另一关键词和城市可执行、无就业在线的任务、零增长后切换、受阻账号不重试、目标停止、用户暂停、预算与任务归属。
- `work/test_adaptive_collection_console.mjs`：启动隔离控制台，走真实创建任务 API、子进程、断点、原生入库、目标调度和状态 API；平台响应全部替换为固定测试数据，禁止真实浏览器。就业在线主词分页停滞后，继续已配置的自动化测试关键词，补充软件测试及测试开发，执行北京与深圳组合，达到 12/12 后停止，不重复请求停滞条件。
- 旧的健康续轮、403 安全停止、关键词同步、接口配置升级和分页保护回归测试继续保留。

上述隔离测试不能证明真实网站仍支持相同请求或一定能交付 8,000 条。真实任务续采时仍可能受到平台结果量、资格、重复岗位或登录状态限制。
