2026-11-13：洞察页面同步核对当前启用分类器的版本、文件摘要、阈值及训练批次；换版后立即清除旧版报告展示，提示重新生成。新模型的首次全库分析不受 20% 增长阈值限制；同版本报告仍按增长策略复用。模型状态尚未核对时不展示未经确认的旧报告，候选训练失败不误判为线上模型升级。两张岗位画像词云按频次展示前 50 个词，标题显示实际词数。

2026-11-13：岗位洞察接入数据库报告快照。选择岗位时读取该岗位及当前分类器版本的历史全库报告；以报告生成时的全库去重岗位数为基准，累计增长不足 20% 时，生成分析直接复用快照，达到 20% 后重新计算。首次分析、分类器版本/阈值或语义标签内容变化、数据量减少时重新生成；失败保留此前成功报告。`GET /api/insights/snapshot?role=岗位名` 查询当前模型对应的快照及增长状态，`GET /api/insights/report?snapshotKey=标识` 读取报告。`POST /api/insights/run` 默认复用，显式传 `forceRefresh: true` 可强制更新。历史报告仅在岗位、模型及分析口径一致时自动接入，无需重新付费打标；各岗位独立保存，切换时直接渲染。

2026-11-13：简历匹配度改为岗位能力要求覆盖率，替代此前的原始重排分和排名百分位。先只阅读完整 JD 抽取固定、去重的主要能力要求，再让 DeepSeek 逐项核对脱敏简历证据；匹配度由代码计算为 `明确符合项数 / 主要能力要求总数 × 100%`，例如 8/10 为 80%。每项等权，部分符合与未体现不计分，明确加分项单列不进入分母；学历、地区和数字工作年限仍单独筛选。结果可展开核对每项 JD 原文、简历证据和判断理由，未评估的岗位显示“待评估”，无明确要求不生成百分比。新建匹配自动评估前 12 个候选，后续可评估本页，沿用本轮预算与断点，不自动追加费用；已评估岗位按覆盖率排序，未评估岗位保留初筛顺序。此百分比反映简历证据覆盖程度，不代表录用概率。

2026-11-12：新增系统内“简历匹配”入口（桌面顶部导航、Web 导航及岗位洞察工具栏，路径 `/matching`）。选择已训练的岗位分类器并上传简历，DeepSeek 解析脱敏能力画像，本机对分类器岗位快照执行 BM25＋向量召回及全文分块重排；学历、经验和地区在排序后筛选，当前匹配度按上方 11 月 13 日的能力要求覆盖率计算。已有结果保留在本机，新建或继续时需明确同意模型调用及预算，上限 ¥0.50；中断保留计算缓存与已发生用量，用量未知时不自动重复请求。运行目录默认 `E:/Codex/work/job-resume-matching`，可通过 `JOB_RESUME_MATCHING_DIR` 配置；本地模型需已安装在 `work/role_screening_models`。简历、画像及匹配结果不随源码发布。

2026-11-11：后端入口迁移到 FastAPI，保留现有 Node.js 采集、标注和助手模块作为受控执行进程。分类器训练、面经训练、聚类和分析由持久化队列调度独立进程；报告读取、参数校验和操作去重由 Python 承担。数据和登录资料沿用原路径，公共端口仍为 8788。首次安装、日常启动、任务恢复及回退见 [FastAPI 后端迁移说明](docs/FastAPI后端迁移_20261111.md)。

2026-11-06：完善助手岗位快照、意图识别、渠道详情采集和分类器管理。
